The Problem Space

Why Not Just Use a Statistical Model?

⚠️
No Safety Guarantees
A model predicting execute with 60% confidence on a destructive command will still act. There's no structural gate to block it.
🔮
Black Box Decisions
Softmax probabilities explain nothing. You can't audit why an intent was chosen, or show which rule triggered a block.
🔄
No Compositional Reasoning
Pure models can't extract structured parameters (entity, operation, time window) from an utterance and validate them against policies.
The NSAI Answer
Keep the model for what it's good at — pattern recognition from text. Add a strict symbolic boundary so that numbers never drive decisions. Rules, predicates, and ontologies handle the rest — deterministically, auditably, safely.

Core Architecture Principle

The Symbolic Boundary — The One Rule That Never Breaks

NEURAL ZONE (below the line)
  • Float scores, logits, probabilities
  • TF-IDF weights, embedding activations
  • Confidence values (0.0–1.0)
  • Raw classifier outputs
SYMBOLIC ZONE (above the line)
  • Predicates: CANDIDATE_EXECUTION
  • Symbols: IntentSymbol("execution")
  • Frames: IntentFrame(intent, entity, ...)
  • Rules, dispatch tables, plan steps
🔒 The Golden Rule
Numbers never cross the symbolic boundary. The rule engine, reasoner, planner, and responder never read a float. They operate on predicates and symbols only.
✓ What this buys us
  • Rules are human-readable JSON — no Python touch required
  • Swap neural backbone without changing symbolic layer
  • Every decision is auditable with a decision trace
  • Structural safety gates — not post-hoc filtering

Level 1 — Training & Inference Deep Dive

Level 1 — Training vs Inference Layer

🏋️ Training Layer
  • L0 → L1 shift: 1 multiclass model → 4 independent binary models (one-vs-rest per intent)
  • Each binary detector trained on same corpus, tuned to fire only for its own intent
  • Scores are independent floats — they do not sum to 1
  • Thresholds (BASE_MIN_SCORE=0.30, HIGH_CONFIDENCE_SCORE=0.85) tuned during training but stored in CONFIG, not in model weights
  • Rules are defined as DEFAULT_RULES in level1_model.py and optionally persisted to rules.json — authored by domain experts, not learned
⚡ Inference Layer
  • 4 detectors run in parallel → 4 raw scores emitted
  • Symbolization converts every score to predicates: threshold logic fires once, here, and nowhere else
  • Rule engine processes predicate set via priority queue: R_INSUFFICIENT_INPUT (P100) → R_NO_CANDIDATE_INTENT (P95) → R_EXECUTION_LOW_CONFIDENCE (P90) → R_AMBIGUOUS (P50) → R_DEFAULT (P0)
  • First matching rule determines decision_state + decision_reason
  • Full decision_trace attached to every output for auditability
{
  "predicted_intent": "execution",
  "decision_state": "needs_clarification",
  "triggered_rules": ["R_EXECUTION_LOW_CONFIDENCE"]
}

Level 3 — Data Transformation

TF-IDF vs Learned Embeddings — What Actually Changes

📊 L0 / L1 — TF-IDF (counting model)
How TF-IDF represents a word
Build a fixed vocabulary of 100 words from the corpus
Each word gets a column index in a 100-wide vector
Each utterance → sparse vector: most entries = 0

"restart nginx"
→ [0, 0, …, 1.23, 0, …, 0.87, …, 0]
   100 dims · 2 non-zero values
Fixed forever: "restart" always gets the same weight regardless of what surrounds it
No semantic link: "restart" and "reboot" are two completely separate columns — zero relationship
No word order: "nginx restart" = "restart nginx" (bag of words)
Sparse: 100 columns, mostly zero — limited capacity
🧠 L3 — Learned Embeddings (learning model)
How embeddings represent a word
Build vocab → assign each word an integer ID
nn.Embedding(vocab_size, 32) → a learnable matrix initialized random

"restart" → ID 42 → row 42 of matrix
→ [0.31, −0.12, 0.84, 0.02, 0.67, …] (32 values)

"reboot" → ID 17 → row 17 of matrix
→ [0.29, −0.11, 0.81, 0.03, 0.65, …] similar! learned
Sequence → single vector: 4 word vectors → mean-pool → one 32-dim vector per utterance
Semantic proximity: words used in similar contexts drift together during training
Gradients flow all the way back: Linear → pool → Embedding. The word representations themselves update each epoch
Dense: 32 dims, all meaningful — no wasted capacity
Level 3 — Symbolic Boundary

The IntentSymbol Contract — How the Boundary Is Enforced

L1 enforced the boundary with thresholds in _symbolize(). L3 enforces it with a typed dataclass — the integer that comes out of argmax is the one and only thing that crosses the line.

INSIDE STAGE 1 (neural, private)
Logits: [−0.3, 2.1, 0.4, −1.2]
Probabilities: never computed here
argmax → 1 (integer, stops here)

Everything above this line
never leaves Stage 1
No softmax · No probability · No confidence score
THE BOUNDARY — Symbol Emitter
# Only thing that crosses:
# class_index: int

index_to_intent = {
    0: "summarization",
    1: "execution",
    2: "investigate",
    3: "out_of_scope"
}

# Validated dataclass:
if index not in index_to_intent:
    raise ValueError(index)

return IntentSymbol(
    intent=index_to_intent[index]
)
Invalid index → exception at the boundary, not a silent bad prediction
INSIDE STAGE 3 (symbolic, public)
Rule engine — if/elif chain
if symbol.intent == "execution":
    action = "route_to_executor"
    requires_approval = True
elif symbol.intent == "investigate":
    action = "trigger_diagnostics"
    requires_approval = False
elif symbol.intent == "summarization":
    action = "call_summarization_pipeline"
    requires_approval = False
else:
    action = "return_safe_fallback"
    requires_approval = False
No numbers · No thresholds
Swap neural model → this routing unchanged
Why this matters: L1's symbolization layer converted 4 float scores into predicates — numbers still existed inside the boundary. L3 goes further: only a single integer crosses. The typed dataclass makes illegal states unrepresentable — you cannot accidentally pass a raw logit into the rule engine.

Key Innovation — Ontology-Driven Domain Swap
All domain knowledge lives in ontology.py — INTENTS, ENTITIES, ENTITY_ALIASES, SYMPTOM_ALIASES, TIME_CONTEXT_PATTERNS. Pipeline stages are domain-agnostic. Swap ontology → new domain, zero code changes, zero retraining.
⚠ All three layers change simultaneously — here's why
Data: corpus gains entity aliases, symptom keywords, time patterns — needed to build IntentFrame.
Neural: deliberately reverts from L3's nn.Embedding back to TF-IDF+LR — the classifier only needs to produce one reliable intent symbol; rich representation adds no value when the pipeline does the heavy lifting.
Symbolic: single dispatch replaced by a full Reason → Plan → Respond chain — because intent alone is not enough to drive an SRE action; you need who (entity), what (symptom), and when (time context) before any decision is safe to make.

Level 4

Level 4 — Symbolically Supervised Neural Model

The symbolic rules move inside training. Ontology constraints are a differentiable loss term — at inference, no symbolic layer exists at all.

Architecture
①
Frozen Encoder — all-MiniLM-L6-v2
384-dim sentence embeddings · frozen throughout training · no fine-tuning
Neural
②
Shared Trunk — Linear(384→256) + ReLU + Dropout
101,644 trainable params · shared representation for all three heads
Neural
③
3 Heads: intent (→4) · entity_type (→7) · domain (→1)
CrossEntropy + CrossEntropy + BCEWithLogits  +  SymbolicConstraintLoss(λ) + DomainIntentCausalLoss(γ)
Symbolic×
Six-Tier Symbolic Constraint Loss (v2 — differentiable)
TYPE_A (×6, w=1.0): out_of_scope + any SRE entity → false rejection
TYPE_B (×2, w=0.75): execution + incident/metric → false execution
TYPE_C (×2, w=0.5): investigate/summarization + unknown → ungrounded
TYPE_D (×1, w=1.25): execution + unknown → hierarchical safety
TYPE_E (cross-head, γ=0.75): domain_conf × p(out_of_scope) → causal
TYPE_F (×1, w=0.4): summarization + metric → temporal mismatch

L = L_intent + α·L_entity + β·L_domain + λ·L_constraint + γ·L_causal

v2 baseline appears higher than v1 (0.132 vs 0.051) — because v2 evaluator now counts TYPE_D and TYPE_F violations that v1 was blind to. Corrective, not regression.
What changes from L3.5 — all three layers again
Data: same intent corpus, but now annotated with entity_type and domain labels — needed to supervise the two new heads.
Neural: completely replaced — frozen MiniLM-L6-v2 (384-dim) replaces the shallow nn.Embedding(32); three prediction heads instead of one; 101,644 trainable params vs ~hundreds.
Symbolic: disappears from inference entirely — rules become SymbolicConstraintLoss(λ) + DomainIntentCausalLoss(γ) during training, then are discarded. No runtime symbolic layer exists.
v2 — Three new constraint families (stronger symbolic supervision)
TYPE_D — Hierarchical (w=1.25): execution+unknown closes the safety gap left by TYPE_B. The execution hierarchy now covers: metric/incident (0.75) → unknown (1.25).
TYPE_E — Causal (γ=0.75): first cross-head constraint — penalises the logical contradiction of predicting both high domain confidence and out_of_scope simultaneously.
TYPE_F — Temporal (w=0.4): summarization+metric penalises retrospective intent on real-time signals — directly addresses the investigate↔summarize confusion observed in L6 failure analysis.
Why this design — the key trade-off
L3.5 enforced rules at runtime — the symbolic layer could correct the model but couldn't update its weights. Every hard-to-classify utterance was a runtime band-aid.

L4 bakes the rules into the loss function so the model learns to never produce a forbidden pair. The gain: zero inference overhead, no symbolic dependency in production. The cost: changing a rule requires retraining — you can't patch it live.

④ Path B — Pre-softmax Gate (toward L5)

→ final_probs ← gradients flow through valid logits only
Gate enters the forward pass — model cannot produce a suppressed intent. Violation rate: 0 by construction. Not yet L5: mask is a per-utterance external filter, not a compiled learned rule module.
Constraint Registry
HARDblock_execute — suppress execute whenever question phrasing detected (cannot be overridden by model confidence) SOFTprefer_investigate — bias toward investigation when uncertainty markers present SOFTallow_execute — permit execute when imperative language detected HARDrequire_diagnostic_investigate — force investigation for system-state questions
What changes from L4 — the architecture simplifies
Data: enriched with 3 boolean facts + per-utterance allowed/suppressed intent lists — the training signal now encodes intent pragmatics, not just label.
Neural: deliberately simpler — back to shallow TF-IDF+Linear. The gate does the safety work; the model only needs to rank plausible intents well.
Symbolic: re-emerges at runtime as a constraint gate — either post-hoc masking (Path A) or pre-softmax logit blocking (Path B). Rules are external, not baked into weights.
Why this design — the key trade-off vs L4
L4 baked constraints into weights via training loss — no runtime gate, but rule changes require retraining. L4.5 inverts this: constraints are live, editable rules applied at inference.

Path B moves the gate inside the forward pass (pre-softmax), so a suppressed intent is structurally impossible to output — violation rate is 0 by construction. This is the conceptual bridge to L5, where the gate becomes a compiled, learned rule module rather than an external per-utterance filter.

Summary

Core NSAI Principles

🔢→🔤
Numbers → Symbols, Once
Threshold logic fires exactly once, in the symbolization layer. Rules, reasoners, planners never read a float. This is the single most important structural decision.
📋
Rules are Data, Not Code
From L1 onward, decision logic lives in JSON files and dispatch dicts — inspectable, versionable, modifiable by domain experts without touching Python.
🔌
Swappable Neural Backbone
The symbolic layer is entirely decoupled from the model. Swap TF-IDF for a transformer — the rule engine, reasoner, and planner don't change at all.
🛡️
Structural Safety vs Post-hoc Masking
L1 blocks at the rule level. L3.5 rejects at the reasoner level. Neither can be defeated by model overconfidence — the symbolic gate is always in the path.
🔍
Full Auditability at Every Level
Every prediction carries a trace: which detectors fired, which rules triggered, which predicates were active. No black-box decisions from L1 onward.
🧩
Ontology = Domain Knowledge Hub
By L3.5, all domain knowledge (entities, aliases, symptoms, time patterns) is centralized in ontology.py. Pipeline stages are domain-agnostic — point at a new ontology and done.
Summary — Advanced Levels

What L4 → L6 Each Unlocks

⚡
L4 — Symbolic Constraints Baked Into Training
L1–L3.5 applied symbolic structure around or after the model. L4 inverts this: constraints enter the training objective via a differentiable SymbolicConstraintLoss(λ) that penalises disallowed (intent, entity_type) pairs during backprop — the weights themselves learn to avoid violations. No runtime symbolic dependency at inference. λ=1.0 → 96.7% accuracy · 3.6% violation rate · TYPE-B violations eliminated.
🚦
L4.5 — Runtime Logic Gating: Post-hoc vs Pre-softmax [Experimental Extension]
Enriches training data with per-utterance symbolic signals (facts → constraints → allowed/suppressed intents). Two runtime paths: post-hoc masking corrects the output after softmax; pre-softmax gating sets suppressed logits to −∞ before softmax — violation rate = 0 by construction. Gate is still an external per-utterance filter, which is what separates L4.5 from L5.
🧬
L5 — Symbolic Rules Compiled Into the Architecture [Research Prototype]
Rules are differentiable modules inside the network. The RuleCompiler evaluates 4 domain rules over 11 learned predicate probabilities using product t-norm (AND = a·b · OR = a+b−ab · NOT = 1−a). Learnable rule_strength×4 parameters are trained jointly with the rest of the network — gradients flow end-to-end through symbolic logic. Result: 98.8% accuracy (+2.1 pp vs L4 λ=1.0) · 0 TYPE-A/B violations · full rule + predicate trace at every inference call.
🌀
L6 — Self-Evolving Symbolic Vocabulary [Research Frontier]
The symbolic vocabulary itself is no longer fixed. Runtime failures cluster in the 11-dim predicate space (HDBSCAN); each cluster births a candidate symbol. Two promotion gates — Stage 1 (Δacc+FPR) and Stage 2 (optional retrain) — validate before rule_base.json is updated. Symbol lifecycle (Active → Weakening → Deprecated) prevents rule bloat. Result: S_001 Δacc=+0.2401 (FPR 3.6%) · S_003 Δacc=+0.2538 (FPR 0%) · 62.3% failure coverage (654/1,050) · 0 human-authored rules.
