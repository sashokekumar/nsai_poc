The Problem Space

Why Not Just Use a Statistical Model?

⚠️
No Safety Guarantees
A model predicting execute with 60% confidence on a destructive command will still act. There's no structural gate to block it.
🔮
Black Box Decisions
Softmax probabilities explain nothing. You can't audit why an intent was chosen, or show which rule triggered a block.
🔄
No Compositional Reasoning
Pure models can't extract structured parameters (entity, operation, time window) from an utterance and validate them against policies.
The NSAI Answer
Keep the model for what it's good at — pattern recognition from text. Add a strict symbolic boundary so that numbers never drive decisions. Rules, predicates, and ontologies handle the rest — deterministically, auditably, safely.

Core Architecture Principle

The Symbolic Boundary — The One Rule That Never Breaks

NEURAL ZONE (below the line)
  • Float scores, logits, probabilities
  • TF-IDF weights, embedding activations
  • Confidence values (0.0–1.0)
  • Raw classifier outputs
SYMBOLIC ZONE (above the line)
  • Predicates: CANDIDATE_EXECUTION
  • Symbols: IntentSymbol("execution")
  • Frames: IntentFrame(intent, entity, ...)
  • Rules, dispatch tables, plan steps
🔒 The Golden Rule
Numbers never cross the symbolic boundary. The rule engine, reasoner, planner, and responder never read a float. They operate on predicates and symbols only.
✓ What this buys us
  • Rules are human-readable JSON — no Python touch required
  • Swap neural backbone without changing symbolic layer
  • Every decision is auditable with a decision trace
  • Structural safety gates — not post-hoc filtering

Level 1 — Training & Inference Deep Dive

Level 1 — Training vs Inference Layer

🏋️ Training Layer
  • L0 → L1 shift: 1 multiclass model → 4 independent binary models (one-vs-rest per intent)
  • Each binary detector trained on same corpus, tuned to fire only for its own intent
  • Scores are independent floats — they do not sum to 1
  • Thresholds (BASE_MIN_SCORE=0.30, HIGH_CONFIDENCE=0.85) tuned during training but stored in CONFIG, not in model weights
  • Rules (rules.json) are authored by domain experts, not learned — zero training dependency
⚡ Inference Layer
  • 4 detectors run in parallel → 4 raw scores emitted
  • Symbolization converts every score to predicates: threshold logic fires once, here, and nowhere else
  • Rule engine processes predicate set via priority queue (R1→R4→R2→R3)
  • First matching rule determines decision_state + decision_reason
  • Full decision_trace attached to every output for auditability
{
  "predicted_intent": "execution",
  "decision_state": "blocked",
  "triggered_rules": [{"rule_id": "R4", "category": "safety"}]
}

Level 3 — Data Transformation

TF-IDF vs Learned Embeddings — What Actually Changes

📊 L0 / L1 — TF-IDF (counting model)
How TF-IDF represents a word
Build a fixed vocabulary of 5,000 words from the corpus
Each word gets a column index in a 5,000-wide vector
Each utterance → sparse vector: most entries = 0

"restart nginx"
→ [0, 0, …, 1.23, 0, …, 0.87, …, 0]
   5,000 dims · 2 non-zero values
Fixed forever: "restart" always gets the same weight regardless of what surrounds it
No semantic link: "restart" and "reboot" are two completely separate columns — zero relationship
No word order: "nginx restart" = "restart nginx" (bag of words)
Sparse: 5,000 columns, mostly zero — wasted capacity
🧠 L3 — Learned Embeddings (learning model)
How embeddings represent a word
Build vocab → assign each word an integer ID
nn.Embedding(vocab_size, 16) → a learnable matrix initialized random

"restart" → ID 42 → row 42 of matrix
→ [0.31, −0.12, 0.84, 0.02, 0.67, …] (16 values)

"reboot" → ID 17 → row 17 of matrix
→ [0.29, −0.11, 0.81, 0.03, 0.65, …] similar! learned
Sequence → single vector: 4 word vectors → mean-pool → one 16-dim vector per utterance
Semantic proximity: words used in similar contexts drift together during training
Gradients flow all the way back: Linear → pool → Embedding. The word representations themselves update each epoch
Dense: 16 dims, all meaningful — no wasted capacity
Level 3 — Symbolic Boundary

The IntentSymbol Contract — How the Boundary Is Enforced

L1 enforced the boundary with thresholds in _symbolize(). L3 enforces it with a typed dataclass — the integer that comes out of argmax is the one and only thing that crosses the line.

INSIDE STAGE 1 (neural, private)
Logits: [−0.3, 2.1, 0.4, −1.2]
Probabilities: never computed here
argmax → 1 (integer, stops here)

Everything above this line
never leaves Stage 1
No softmax · No probability · No confidence score
THE BOUNDARY — Symbol Emitter
# Only thing that crosses:
# class_index: int

index_to_intent = {
    0: "summarization",
    1: "execution",
    2: "investigate",
    3: "out_of_scope"
}

# Validated dataclass:
if index not in index_to_intent:
    raise ValueError(index)

return IntentSymbol(
    intent=index_to_intent[index]
)
Invalid index → exception at the boundary, not a silent bad prediction
INSIDE STAGE 3 (symbolic, public)
Dispatch table — pure dict
DISPATCH = {
  "execution": {
    "action": "execute_w_approval",
    "requires_approval": true
  },
  "investigate": {
    "action": "run_query",
    "requires_approval": false
  },
  "summarization": {
    "action": "generate_report",
    "requires_approval": false
  }
}
No if/elif · No numbers · No thresholds
Swap neural model → this dict unchanged
Why this matters: L1's symbolization layer converted 4 float scores into predicates — numbers still existed inside the boundary. L3 goes further: only a single integer crosses. The typed dataclass makes illegal states unrepresentable — you cannot accidentally pass a raw logit into the rule engine.

Level 4

Level 4 — Symbolically Supervised Neural Model

The symbolic rules move inside training. Ontology constraints are a differentiable loss term — at inference, no symbolic layer exists at all.

Architecture
①
Frozen Encoder — all-MiniLM-L6-v2
384-dim sentence embeddings · frozen throughout training · no fine-tuning
Neural
②
Shared Trunk — Linear(384→256) + ReLU + Dropout
101,644 trainable params · shared representation for all three heads
Neural
③
3 Heads: intent (→4) · entity_type (→7) · domain (→1)
CrossEntropy + CrossEntropy + BCEWithLogits  +  SymbolicConstraintLoss(λ)
Symbolic×
The Constraint Loss (differentiable)
10 disallowed (intent, entity_type) pairs from constraint_rules.json
TYPE_A (×6, w=1.0): out_of_scope + any SRE entity → false rejection
TYPE_B (×2, w=0.75): execution + incident/metric → false execution
TYPE_C (×2, w=0.5): investigate/summarization + unknown → ungrounded

L_total = L_intent + α·L_entity + β·L_domain + λ·L_constraint
λ Ablation Results (test set n=333)
Run Intent Acc Viol Rate TYPE_B
L3.5 runtime 0.931 0.643 0.000
L4 λ=0.0 0.970 0.051 0.003
L4 λ=0.1 0.970 0.045 0.000

Logic is external and non-differentiable. The model internally still assigns full probability to suppressed intents — only the output is corrected.
④ Path B — Pre-softmax Gate (toward L5)
raw_logits → mask suppressed → −∞

Gate enters the forward pass — model cannot produce a suppressed intent. Violation rate: 0 by construction. Not yet L5: mask is a per-utterance external filter, not a compiled learned rule module.

L4.5 reintroduces a runtime gate — but moves it inside the forward pass (pre-softmax), so gradients flow through constrained outputs. This is the bridge from trained constraints to architecturally compiled rules (L5). L4 inverts this — symbolic rules shape the model during training, then disappear at inference. The boundary moves from runtime to gradient.

Summary

Core NSAI Insights

🔢→🔤
Numbers → Symbols, Once
Threshold logic fires exactly once, in the symbolization layer. Rules, reasoners, planners never read a float. This is the single most important structural decision.
📋
Rules are Data, Not Code
From L1 onward, decision logic lives in JSON files and dispatch dicts — inspectable, versionable, modifiable by domain experts without touching Python.
🔌
Swappable Neural Backbone
The symbolic layer is entirely decoupled from the model. Swap TF-IDF for a transformer — the rule engine, reasoner, and planner don't change at all.
🛡️
Structural Safety vs Post-hoc Masking
L1 blocks at the rule level. L3.5 rejects at the reasoner level. Neither can be defeated by model overconfidence — the symbolic gate is always in the path.
🔍
Full Auditability at Every Level
Every prediction carries a trace: which detectors fired, which rules triggered, which predicates were active. No black-box decisions from L1 onward.
🧩
Ontology = Domain Knowledge Hub
By L3.5, all domain knowledge (entities, aliases, symptoms, time patterns) is centralized in ontology.py. Pipeline stages are domain-agnostic — point at a new ontology and done.
⚡
L4 — Symbolic Constraints Baked Into Training
L1–L3.5 applied symbolic structure around or after the model. L4 inverts this: symbolic constraints enter the training objective itself via a differentiable SymbolicConstraintLoss(λ) that penalises disallowed (intent, entity_type) pairs during backprop — so the weights themselves learn to avoid violations. At inference there is no symbolic gate; the constraint is already encoded in the parameters. λ=1.0 achieves 96.7% intent accuracy with only 3.6% constraint violations — TYPE_B violations eliminated entirely.
🚦
L4.5 — Runtime Logic Gating: Post-hoc vs Pre-softmax
L4.5 enriches the training signal with per-utterance symbolic data (facts → constraints → allowed/suppressed intents) and then applies logic at inference. Two distinct approaches are compared: post-hoc masking zeros suppressed intents after softmax (non-differentiable, corrects output); pre-softmax gating masks suppressed logits to −∞ before softmax so gradients only flow through valid intents — violation rate is exactly 0 by construction. The gate is still a per-utterance external filter (not a learned rule module), which is the distinction that separates L4.5 from strict Level 5.
